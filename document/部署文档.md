## 一、部署方式

项目是纯静态单页，没有构建步骤、包管理或运行时依赖。GitHub Pages 直接从 `static` 分支根目录读取文件：

- `index.html`
- `assets/styles.css`、`assets/app.js`
- `assets/fonts/`、`assets/images/`
- `.nojekyll`（空文件，跳过 Jekyll 处理）

Vercel 已停用，本地 `.vercel/` 配置已删除，仓库中不再保留 Vercel 相关文件。

## 二、首次启用（仓库设置）

GitHub Pages 需要在该仓库启用一次：

1. 打开 https://github.com/zpq990/stone_research_agent/settings/pages
2. **Build and deployment → Source** 选择 **Deploy from a branch**
3. **Branch** 选择 `static`，目录选择 `/ (root)`
4. 点击 **Save**

保存后 GitHub 会开始首次发布，通常 1–2 分钟内完成。发布状态可在仓库的 **Actions** 或 **Deployments** 里查看。

> 如果 `static` 分支尚未推送，先执行 `git push -u origin static`。

## 三、日常发布流程

所有前端改动在 `static` 分支提交并推送即可：

```bash
git checkout static
git add <改动文件>
git commit -m "<说明>"
git push
```

Pages 检测到 `static` 有新提交后自动重新发布，无需手动构建或上传产物。

## 四、发布后验证

1. 打开 https://zpq990.github.io/stone_research_agent/ ，确认首屏 H1、样本报告卡正常显示。
2. 检查样式与字体是否加载：页面应为纸色 / 石色底、胡桃木按钮，中文为衬线标题 + 无衬线正文。
3. 点击页头三个导航，确认折叠区正常展开且一次只开一段。
4. 直接访问 `#report`、`#method`、`#faq` 链接，确认对应折叠自动展开。
5. 手机宽度下检查 Hero 单列、对照表堆叠、照片带 2×2。
6. 若浏览器缓存了旧版本，强制刷新（Ctrl/Cmd + Shift + R）后复查。

## 五、注意事项

- **路径必须相对**：站点发布在 `/stone_research_agent/` 子路径下，资源引用不能写成 `/assets/...`，否则会 404。当前页面全部使用相对路径。
- **文件名大小写敏感**：GitHub Pages 区分大小写，图片和字体文件名必须与 HTML / CSS 中完全一致。
- **`.nojekyll` 不要删**：它让 Pages 按静态文件原样发布，避免下划线开头的目录或文件被 Jekyll 忽略。
- **不需要 404 重写**：这是单页静态站，所有导航都是页内锚点，不依赖 SPA 路由。
- **仓库可见性**：GitHub Pages 站点默认公开；若仓库为私有，需确认账号的 Pages 权限。
- **回滚**：用 `git revert <提交>` 生成反向提交并推送，Pages 会自动回到上一版本；不要用强推改写 `static` 历史。
